# Сторонние компоненты и заимствования

Этот документ предназначен для учёта стороннего кода, шаблонов и других материалов, включённых в RED Virt Log Viewer.

## 2. Кандидаты для переиспользования

Таблица описывает план, а не завершённый перенос.

| Исходный путь | Назначение | Планируемое использование |
| --- | --- | --- |
| `src/format_templates.txt` | Шаблоны форматов журналов | Проверенные шаблоны Engine и VDSM с адаптацией к контракту парсеров |
| `src/lib/detect_running_components.py` | Извлечение объектов и распознавание операций | Отдельные проверенные правила; без переноса модели объектов целиком |
| `src/lib/create_error_definition.py` | Обработка записей и продолжений | Изучение подходов; перенос только после проверки конкретного фрагмента |
| `src/lib/represent_statistics.py` | Представление результатов с привязкой к источнику | Изучение подхода к навигации; копирование кода пока не запланировано |

Полный CLI, `pickle`-кеш и архитектура старого анализатора не входят в согласованный план переноса.

## 3. Реестр фактических заимствований

- **Компонент:** ovirt-log-analyzer

- **Заимствованный материал:** регулярные выражения заголовков Engine и VDSM
- **Путь в RED Virt Log Viewer:** `parsers/engine.py`, `parsers/vdsm.py`
- **Лицензия:** Apache License, Version 2.0
- **Уведомления об авторстве:** в шапках указанных файлов; отдельный NOTICE в upstream не найден
- **Изменения:** именованные группы заполнены; часовой пояс разбирается в `core/timeparse.py` (включая `+03:30`, `+10`, `+0800`, `Z`); завершающий `(file:line)` в VDSM необязателен; `vmId` пишется в identifiers, не в сущности ВМ
- **Сопровождающие файлы:** `licenses/ovirt-log-analyzer-Apache-2.0.txt`

Для копии текста лицензии используется `licenses/ovirt-log-analyzer-Apache-2.0.txt`.

## 4. Сопровождение переноса и распространения

При фактическом включении материалов `ovirt-log-analyzer` выполнить требования Apache-2.0, в том числе:

- включить копию текста лицензии в распространяемый пакет;
- сохранить применимые исходные уведомления;
- заметно обозначить изменения в модифицированных файлах;
- учесть содержимое upstream-файла `NOTICE`, если он присутствует в выбранной версии и применим к включённым материалам.

Основание: раздел 4 файла [LICENSE проверенной версии](https://github.com/mz-pdm/ovirt-log-analyzer/blob/ad6179a6622e49bc4f1682c16486555c04f29edb/LICENSE).

Для копии текста лицензии используется путь `licenses/ovirt-log-analyzer-Apache-2.0.txt`.

Этот документ не задаёт лицензию собственного кода RED Virt Log Viewer. Она выбирается отдельно и отражается в корневом `LICENSE` и `README.md`.

## 5. Зависимости и документация

Набор зависимостей плагина пока не зафиксирован. Пакеты, установленные только для исследования upstream-анализатора, не считаются автоматически зависимостями RED Virt Log Viewer.

При добавлении или включении в пакет сторонней библиотеки необходимо проверить её версию, лицензию и требуемые уведомления. Встроенные модули Python и внешние пакеты следует различать в документации установки.

Документация Sublime Text, РЕД СОФТ, oVirt и Libvirt/QEMU используется как справочный материал. Сама ссылка на документацию не означает включение её содержимого в проект. Если текст, примеры, изображения или другие материалы копируются, их происхождение и условия использования учитываются отдельно.

## 6. Образцы логов

Клиентские логи не являются частью upstream-компонента. Лицензия `ovirt-log-analyzer` не определяет условия публикации этих данных.

В репозиторий должны попадать только минимальные образцы, подготовленные для публикации: с обезличиванием имён, адресов, идентификаторов и других чувствительных данных. Преобразование связанных образцов должно сохранять согласованность замен, необходимую для тестов.

Полные архивы обращений и необезличенные журналы в распространяемый пакет не включаются. Происхождение, преобразования и назначение тестовых образцов описываются отдельно в `tests/fixtures/README.md`.

Перед подготовкой устанавливаемого пакета сопоставить документ с фактическим содержимым проекта:

1. Заполнены записи обо всех включённых сторонних материалах.
2. Версии и ссылки соответствуют реально перенесённому коду.
3. Необходимые тексты лицензий и уведомления включены в пакет.
4. Изменения заимствованных файлов обозначены.
5. Планируемые компоненты не представлены как уже используемые.
6. Собственная лицензия проекта определена отдельно.
7. Клиентские архивы и необезличенные данные отсутствуют в поставке.
